# Auto Email — Google Apps Script

เว็บแอปนี้ทำให้ปุ่ม **✉ ดราฟอีเมล** สร้าง **แบบร่างตอบกลับ** ใน Gmail ของคนที่กด และเก็บกฎไว้บน Google Sheet ที่ทั้งทีมใช้ร่วมกัน

สคริปต์ **ไม่มีคำสั่งส่งอีเมล** ไม่มี `send`, `GmailApp`, `Drafts.send` หรือ `Messages.send` ผลลัพธ์มีแต่แบบร่าง

หน้า `auto-email.html` บน GitHub Pages เรียกเว็บแอปนี้ทางป๊อปอัป ไม่ใช่ `fetch()` เพราะเว็บแอปแบบ «รันในนามผู้ใช้» จะเด้งไปหน้าล็อกอินของ Google และไม่ส่งหัว CORS รายละเอียดอยู่ท้ายไฟล์นี้

repo นี้ยังไม่ได้ถูกดีพลอยขึ้น Workspace ของบริษัท การทดสอบในเครื่องตรวจได้แค่ตรรกะจับคู่กฎและหน้าเว็บ ขั้นตอนด้านล่างต้องทำให้บนบัญชี Google Workspace จริง

## สิทธิ์ที่ขอ (น้อยที่สุดที่งานนี้ใช้ได้)

| สโคป | ใช้ทำอะไร |
| --- | --- |
| `gmail.compose` | สร้างแบบร่างตอบกลับ สโคปนี้ของ Google รวมความสามารถส่งด้วย แต่โค้ดไม่ได้เรียกส่ง |
| `gmail.readonly` | อ่านเธรดหรือค้นจดหมายเดิม เพื่อเอาหัวข้อและ Message-ID มาผูกแบบร่าง |
| `spreadsheets` | อ่านและเขียนชีตกฎ |
| `userinfo.email` | ตรวจว่าผู้ใช้เป็น `@hungryhub.com` |
| `script.external_request` | เรียก LLM เมื่อเปิดใช้เท่านั้น ถ้าไม่ตั้งค่า จะไม่มีการยิงออกเน็ต |

ใช้ **Gmail API (advanced service)** ไม่ใช้ `GmailApp` เพราะ `GmailApp` จะขอสิทธิ์อ่านทั้งกล่อง (`https://mail.google.com/`)

การดีพลอยแบบ «เฉพาะคนในโดเมน» ต้องใช้บัญชี Google Workspace ไม่ใช่ Gmail ส่วนตัว `@gmail.com`

## 1. สร้างชีตกฎ

1. สร้าง Google Sheet ใหม่ ตั้งชื่อเช่น `Hungry Hub Auto Email rules`
2. เปลี่ยนชื่อแท็บแรกเป็น `Rules`
3. ใส่หัวคอลัมน์แถวที่ 1 ให้ตรงนี้ทุกตัว พิมพ์เล็กใหญ่ตรงกัน

```
id	name	enabled	keywords	template	countries	language	updatedBy	updatedAt
```

4. แถวตัวอย่าง (คัดลอกได้) คอลัมน์ `keywords` หนึ่งคำต่อหนึ่งบรรทัดในเซลล์เดียวกัน

| id | name | enabled | keywords | template | countries | language |
| --- | --- | --- | --- | --- | --- | --- |
| seed-etax | ขอใบกำกับภาษี | TRUE | ขอใบกำกับภาษี และขึ้นบรรทัดใหม่ ใบกำกับภาษี e-Tax | เรียน คุณลูกค้า ทางเราได้ส่งใบกำกับภาษี (e-Tax) แล้วค่ะ | TH | th |
| seed-billing | ขอข้อมูลวางบิล | TRUE | ข้อมูลการวางบิล | เรียน คุณลูกค้า รอบวางบิลของเราคือสิ้นเดือนค่ะ | TH,SG,MY | en |

`countries` คั่นด้วยจุลภาค `language` เป็น `th`, `en` หรือ `match`  
`updatedBy` กับ `updatedAt` สคริปต์เขียนให้เองตอนบันทึก

5. กด **แชร์** แล้วให้คนในโดเมน `hungryhub.com` เป็น **ผู้แก้ไข (Editor)**  
   สคริปต์รันในนามคนที่กด ถ้าชีตแชร์แค่เจ้าของ คนอื่นจะสร้างแบบร่างในกล่องตัวเองได้ แต่เขียนกฎไม่ได้

6. คัดลอกรหัสชีตจาก URL  
   `https://docs.google.com/spreadsheets/d/`**`รหัสนี้`**`/edit`

## 2. สร้างโปรเจกต์ Apps Script

1. เปิด [script.google.com](https://script.google.com) ด้วยบัญชี Workspace แล้วสร้างโปรเจกต์ใหม่ ชื่อ `Hungry Hub Auto Email`
2. ลบโค้ดใน `Code.gs` แล้ววางเนื้อหาจาก `apps-script/Code.gs` ใน repo นี้
3. กด **+** ข้างไฟล์ เลือก **Script** ตั้งชื่อไฟล์ว่า `matching` แล้ววางเนื้อหาจาก `apps-script/matching.js`  
   ไฟล์นี้ต้องอยู่ในโปรเจกต์เดียวกัน เพราะฟังก์ชันจับคู่กฎอยู่ที่นี่
4. กด **+** เลือก **HTML** ตั้งชื่อไฟล์ว่า `Bridge` แล้ววางเนื้อหาจาก `apps-script/Bridge.html`
5. เปิด **การตั้งค่าโปรเจกต์** (ไอคอนเฟือง) แล้วติ๊ก **แสดงไฟล์ manifiesto "appsscript.json" ในตัวแก้ไข**
6. เปิด `appsscript.json` แล้วแทนที่ทั้งไฟล์ด้วย `apps-script/appsscript.json` จาก repo  
   ไฟล์นี้เปิด Gmail API เวอร์ชัน v1 ไว้แล้ว และล็อกสโคปตามตารางด้านบน
7. ถ้าเมนู **บริการ (Services)** ยังไม่เห็น Gmail API ให้กด **+** เพิ่ม **Gmail API** ตัวระบุในโค้ดต้องเป็น `Gmail`

อย่าเพิ่มสโคป `https://mail.google.com/` และอย่าใส่คีย์ API ลงในไฟล์

## 3. ค่า Script Properties

ในโปรเจกต์ Apps Script ไปที่ **การตั้งค่าโปรเจกต์ → คุณสมบัติสคริปต์ (Script properties)** แล้วเพิ่ม

| คีย์ | ค่า | จำเป็น |
| --- | --- | --- |
| `RULES_SHEET_ID` | รหัสชีตจากขั้นที่ 1 | ใช่ |
| `ALLOWED_DOMAIN` | `hungryhub.com` | ไม่ใส่ก็ได้ ค่าเริ่มต้นคือโดเมนนี้ |
| `ALLOWED_ORIGINS` | ต้นทางของหน้าเว็บ คั่นด้วยจุลภาค ไม่มี path ท้าย | ใช่ |

ตัวอย่าง `ALLOWED_ORIGINS` เมื่อหน้าอยู่บน GitHub Pages และจะลองจากเครื่องตัวเองด้วย

```
https://kaiphit-hh.github.io,http://localhost:8765,http://127.0.0.1:8765
```

ใส่ได้เฉพาะ `https://ชื่อโฮสต์` หรือ `http://localhost` / `http://127.0.0.1` พร้อมพอร์ต ต้นทางที่ไม่อยู่ในรายการนี้จะกดยืนยันแล้วสคริปต์ไม่รับ

ลายเซ็นท้ายแบบร่าง (ไม่บังคับ)

| คีย์ | ใช้เมื่อภาษาตอบกลับเป็น |
| --- | --- |
| `DRAFT_SIGNATURE_TH` | ไทย ค่าเริ่มต้น `ทีมบัญชี Hungry Hub` |
| `DRAFT_SIGNATURE_EN` | อังกฤษ ค่าเริ่มต้น `Hungry Hub Accounting` |

## 4. ดีพลอยเป็นเว็บแอป

1. กด **ทำให้ใช้งานได้ → การทำให้ใช้งานได้ใหม่** ชนิด **เว็บแอป**
2. **ดำเนินการในนาม:** ผู้ใช้ที่เข้าถึงเว็บแอป (User accessing the web app)  
   ต้องเป็นค่านี้ ถ้าเลือก «ฉัน» แบบร่างจะไปกองที่กล่องของเจ้าของสคริปต์
3. **ใครมีสิทธิ์เข้าถึง:** เฉพาะคนในโดเมน `hungryhub.com` (Anyone within the domain)
4. กด **ทำให้ใช้งานได้** แล้วยอมรับสิทธิ์ด้วยบัญชีตัวเองครั้งแรก
5. คัดลอก URL ที่ลงท้ายด้วย `/exec` เช่น  
   `https://script.google.com/macros/s/xxxxxxxxxxxxx/exec`  
   URL ที่ลงท้าย `/dev` ใช้ไม่ได้กับหน้าเว็บ
6. ทุกครั้งที่แก้โค้ด ต้องกด **ทำให้ใช้งานได้ → จัดการการทำให้ใช้งานได้ → ดินสอ → เวอร์ชัน: เวอร์ชันใหม่ → ทำให้ใช้งานได้** URL `/exec` เดิมยังใช้ได้

พนักงานแต่ละคนจะถูกขอให้อนุญาตครั้งแรกที่กดปุ่มบนหน้าเว็บ แบบร่างไปอยู่ที่กล่องของคนนั้น (`Session.getActiveUser`)

## 5. ผูกกับหน้าเว็บ

เปิด `auto-email.html` แล้วตั้งค่าบรรทัดนี้เป็น URL `/exec` จริง

```javascript
var WEB_APP_URL = "";
```

ถ้าว่าง หน้าจะทำงานแบบเดิม: กฎอยู่ใน `localStorage` ของเบราว์เซอร์ และปุ่มดราฟเป็นแค่ตัวอย่าง ไม่ยิงออกไปไหน

พารามิเตอร์ `?webapp=` ใช้ได้เฉพาะตอนเปิดจาก `localhost` หรือ `127.0.0.1` และต้องเป็น URL `/exec` ของ `script.google.com` เท่านั้น ลิงก์บน GitHub Pages เปลี่ยนปลายทางเองไม่ได้ เพื่อไม่ให้คนอื่นชี้หน้านี้ไปที่สคริปต์คนละตัว

หลังจากตั้งค่าแล้วให้พนักงานเปิด `auto-email.html`

1. กด **เชื่อมต่อชีต** หน้าต่าง Google เปิดขึ้น ล็อกอินถ้ายังไม่ได้ล็อกอิน แล้วกด **ยืนยัน**  
   หน้านี้ไม่ดึงชีตเองตอนโหลด เพราะเบราว์เซอร์ไม่อนุญาตให้เปิดป๊อปอัปโดยที่ผู้ใช้ยังไม่กด
2. กด **บันทึกกฎ** เมื่ออยากให้ทั้งทีมเห็นกฎที่แก้บนจอ การลบบนจอมีผลบนชีตเมื่อกดบันทึก
3. กด **✉ ดราฟอีเมล** สคริปต์จับคู่กฎบนชีตเอง (ไม่ใช้เทมเพลตที่เบราว์เซอร์ส่งมา) แล้วสร้างแบบร่างตอบในเธรด  
   ถ้าสำเร็จ หน้าต่างจะมีลิงก์ไปที่แบบร่างใน Gmail

อีเมลในตารางเป็นข้อมูลตัวอย่าง ไม่มีรหัสเธรดจริง ช่อง **รหัสเธรดหรือข้อความ Gmail** ใช้วางรหัสจากอีเมลจริง (ตัวอักษร a–f และตัวเลข ความยาว 10–32) ถ้าว่าง สคริปต์จะค้นในกล่องของคนที่กดจากหัวข้อ ย้อนหลัง 60 วัน ถ้าใส่รหัสแล้วไม่พบเธรดนั้น สคริปต์จะไม่ไปค้นต่อ และจะไม่สร้างแบบร่างและไม่ส่ง

## 6. เปิดใช้ LLM (ไม่บังคับ)

ค่าเริ่มต้นแต่งข้อความแบบตายตัว ไม่ต่อเน็ต: คำทักทายด้วยชื่อผู้ส่ง, ตัดคำว่า «เรียน คุณลูกค้า» หรือ `Dear customer` ออกจากเทมเพลต, บรรทัดเรื่อง, แล้วตามด้วยลายเซ็น

ถ้าอยากให้โมเดลช่วยเรียบเรียงโดยยึดเทมเพลตเป็นข้อเท็จจริง ให้เพิ่ม Script properties

| คีย์ | ค่า |
| --- | --- |
| `DRAFT_ADAPTER` | `llm` |
| `LLM_API_KEY` | คีย์จากผู้ให้บริการ ใส่ใน Script properties เท่านั้น ห้ามเขียนลงไฟล์หรือคอมมิต |
| `LLM_API_URL` | ไม่ใส่ก็ได้ ค่าเริ่มต้น `https://api.openai.com/v1/chat/completions` |
| `LLM_MODEL` | ไม่ใส่ก็ได้ ค่าเริ่มต้น `gpt-4o-mini` |

ถ้าไม่มีคีย์ หรือผู้ให้บริการตอบไม่สำเร็จ สคริปต์กลับไปใช้เทมเพลตและบอกเหตุผลบนหน้าผลลัพธ์ คีย์ไม่ถูกส่งกลับมาที่เบราว์เซอร์

จากนั้นดีพลอยเวอร์ชันใหม่ตามข้อ 4.6

## สิ่งที่ป๊อปอัปทำ และขีดจำกัด

`fetch()` จาก GitHub Pages ไปที่เว็บแอปนี้ใช้ไม่ได้ Google ตอบด้วยหน้าล็อกอิน และไม่ใส่หัว `Access-Control-Allow-Origin` JSONP ก็พาผู้ใช้ผ่านล็อกอินไม่ได้เหมือนกัน

ทางที่ใช้คือป๊อปอัป

1. หน้าเว็บเปิด `.../exec?page=bridge&req=` ตามด้วยคำขอที่เข้ารหัส base64url  
   ใส่ใน URL เพราะ Chrome ล้าง `window.name` ทันทีที่ข้ามโดเมนไป `script.google.com` ค่านี้จึงไปไม่ถึงหน้ายืนยัน  
   พารามิเตอร์อยู่ใน URL ที่เบราว์เซอร์ส่งให้ Apps Script อยู่แล้ว ไม่ได้พึ่ง CORS
2. ผู้ใช้ต้องกด **ยืนยัน** ในหน้าของ Google เอง กันเว็บอื่นแอบเปิดเว็บแอปนี้ในนามคนที่ล็อกอินค้างไว้
3. หน้าบริดจ์เรียก `google.script.run` แล้วพยายาม `postMessage` กลับไปที่แท็บเดิม เฉพาะต้นทางที่อยู่ใน `ALLOWED_ORIGINS`
4. หน้าล็อกอินของ Google มักตั้ง `Cross-Origin-Opener-Policy` จน `window.opener` หาย ในกรณีนั้นป๊อปอัปจะเด้งไปที่ `auto-email-bridge.html` บนโฮสต์เดียวกับแดชบอร์ด แล้วเขียนผลลง `localStorage` แท็บเดิมรับรู้ผ่านเหตุการณ์ `storage`

ขีดจำกัดที่ควรรู้

- ต้องอนุญาตป๊อปอัปของไซต์นี้ ถ้าเบราว์เซอร์บล็อก จะไม่มีแบบร่าง
- คำขอที่เข้ารหัสแล้วยาวเกิน 12,000 ตัวอักษรจะถูกปฏิเสธ และไม่มีอะไรถูกสร้าง กฎตัวอย่างสามข้ออยู่ในขอบเขตนี้ เทมเพลตที่ยาวมากหลายสิบข้ออาจเกิน
- เนื้อหาอีเมลที่ส่งไปจับคู่ถูกตัดที่ 1,500 ตัวอักษรแรก คีย์เวิร์ดที่อยู่ถัดจากนั้นจะไม่ถูกเห็นโดยเซิร์ฟเวอร์
- ระหว่างยืนยัน คำขออยู่ในแถบที่อยู่ของป๊อปอัป สคริปต์ไม่ได้เขียนค่านั้นลงล็อก
- ผลที่ส่งกลับทางแฮชมีเพดานประมาณ 120,000 ตัวอักษรหลังเข้ารหัส
- ต้นทางที่รับผลต้องตรงกับ `ALLOWED_ORIGINS` และทางกลับต้องเป็น path ที่ลงท้าย `auto-email-bridge.html` เท่านั้น
- ปุ่มบนจอจับคู่กับกฎที่กำลังแก้ เพื่อแสดงแท็ก ส่วนเซิร์ฟเวอร์จับคู่กับกฎบนชีต กฎที่ยังไม่กดบันทึกจะไม่ถูกใช้ตอนสร้างแบบร่าง
- คนที่กดยืนยันทั้งที่ไม่ได้ตั้งใจ จะได้แบบร่างในกล่องตัวเอง แต่ส่งออกไปไม่ได้ และเว็บที่ไม่อยู่ใน `ALLOWED_ORIGINS` จะไม่ได้รับเนื้อแบบร่างกลับไป
- เจ้าของสคริปต์ที่แก้ Script properties ได้เท่านั้นที่ใส่ URL ของ LLM ได้ อย่าใส่ URL ที่ไม่ใช่ของผู้ให้บริการที่ตั้งใจใช้

## ตรวจในเครื่อง โดยไม่ต้องมี Workspace

```bash
node --test apps-script/matching.test.js
```

เทสนี้ตรวจการจับคู่คำแบบตรงตัว กรองประเทศ ภาษา เทมเพลต แถวในชีต และการที่ไฟล์สคริปต์ไม่มีคำสั่งส่งเมล ไม่ได้สร้างแบบร่างจริงใน Gmail
